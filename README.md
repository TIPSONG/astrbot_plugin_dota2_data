# Dota2 数据查询 · AstrBot

让现有的 AstrBot 角色通过工具查询 Dota2 数据，再由原来的对话流程回答。插件负责取数、筛选、统计和返回依据，不创建另一套聊天人格。

**当前版本：`0.2.1-dev`，已通过隔离测试及双数据源真实查询。** 38 项自动测试通过，并验证了 OpenDota、STRATZ 的六类查询及英雄／胜负组合筛选。没有安装到正在运行的 Bot；QQ、实际聊天模型和其他插件共同启用时的完整对话链路仍待验收。详见 [测试报告](docs/TEST_REPORT.md)。

仓库：<https://github.com/TIPSONG/astrbot_plugin_dota2_data>

## 使用方式

正常向当前角色提问即可，例如：

- “查一下我昨天的 Dota 战绩。”
- “我斧王最近十把，只看天梯。”
- “比较这两个账号最近一周的表现。”
- “看看这场比赛的数据，比赛编号是……。”
- “这版本有什么热门英雄？”
- “把这个 Dota 账号绑定到我：……。”

需要 AstrBot `>=4.28.2`、Python `>=3.10`，以及支持 AstrBot 工具调用的当前聊天模型；插件也要在对应配置中启用。依赖为 `aiohttp` 与 `tzdata`（提供包括 Windows 环境在内的时区数据）。本轮没有执行依赖安装。

群聊仍沿用 AstrBot 原有的唤醒、回复与权限规则；本插件不会因为群内出现游戏词语就自行回复。账号首次绑定需要提供真实 Dota 账号 ID 或 Steam64 ID；插件不会从昵称推断一个账号就是你本人。

聊天中绑定、换绑或解绑会先返回待确认信息；用户在下一条消息中明确回复“确认”，且仍在五分钟有效期内，才会保存。待确认操作不会跨插件重载保留。管理面板的已登录管理员通过表单直接管理绑定。

自然语言理解和最终措辞由现有主模型负责。插件提供结构化查询能力，不额外调用聊天、嵌入或重排序模型。

## 当前实现范围

| 能力 | 返回内容与边界 |
| --- | --- |
| 玩家资料 | 公开账号资料与可取得的统计 |
| 条件战绩 | 按英雄、日期、胜负、普通／天梯／加速模式筛选 |
| 单场详情 | 基础数据和数据源已提供的解析信息；不会自动提交录像解析 |
| 英雄池 | 查询公开英雄使用统计，并标明统计口径 |
| 多人对比 | 在相同查询条件下比较玩家；可只比较共同出现的对局 |
| 英雄版本统计 | 获取公开英雄聚合数据，保留来源与统计限制 |
| 账号绑定 | 按会话及消息发送者保存；“我”解析为该会话内本人绑定 |
| 管理面板 | 状态、条件查询、账号绑定、插件设置和查询记录 |

账号绑定不会自动从一个群复制到另一个群或私聊。昵称别名只在对应会话中解析，重名或身份不明确时需要澄清。公开数字账号可以直接查询，无需先绑定。

## 对话和人设边界

- 通过原生工具把结果交还给主模型；不替代原来的回答流程。
- 不编辑人格正文，不添加 Dota 角色设定，不修改现有记忆或陪伴插件的数据。
- 不注册关键词抢答，不主动向会话发送查询结果，不开启后台战报广播。
- 不自行调用另一套模型生成点评，也不需要填写独立聊天模型 API Key。

这些是插件的实现边界，不代表语言模型本身绝不会出现措辞变化或判断错误。主模型能否正确选择工具、理解数据限制并保持角色表达，属于后续运行验收的一部分。

## 管理面板

面板源码位于 `pages/dashboard/`，通过 AstrBot 提供的视图 bridge 请求插件 API，不单独启动 HTTP 服务，不在浏览器保存 AstrBot 登录令牌。`pages/` 是本机 AstrBot 4.28.2 实际扫描的目录。

面板用于管理员管理数据查询服务：

- **概览：**查看本地数据、缓存与请求计数；没有请求成功证据时不宣称数据源在线。
- **查询：**用表单组合条件并查看结构化结果。自然语言入口仍在平常聊天中，面板不是额外的聊天机器人。
- **绑定：**查看、保存或删除会话与用户的账号对应关系。
- **设置：**选择优先数据源与失败回退策略，调整超时、缓存、查询数量和请求预算；可选填写 OpenDota Key 或 STRATZ Token。
- **记录：**查看有限的查询摘要，帮助区分空结果、参数错误和数据源失败。

面板已在隔离环境中使用实际 AstrBot bridge 和处理器验证设置保存、绑定和查询，完成桌面与 390px 窄屏检查。正式 Dashboard 的登录态及插件入口仍需在安装后验收；隔离测试没有绕过或修改正式实例的鉴权。

## 默认配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `true` | 查询服务总开关 |
| `timeout_seconds` | `15` | 单次网络请求超时 |
| `cache_ttl_seconds` | `300` | 查询缓存有效期（秒） |
| `max_matches` | `50` | 单次返回对局数量上限 |
| `scan_limit` | `500` | 条件查询最多扫描的候选对局数 |
| `requests_per_minute` | `30` | 插件主动限制的每分钟请求预算 |
| `daily_request_limit` | `1000` | 插件主动限制的每日请求预算 |
| `timezone` | `Asia/Hong_Kong` | “昨天”“本周”等日期的解释时区 |
| `data_source_priority` | `opendota` | 优先数据源，可选 `opendota` 或 `stratz` |
| `fallback_enabled` | `true` | 初次取数失败时允许使用可用的另一数据源 |
| `opendota_api_key` | 空 | 可选的 OpenDota API Key |
| `stratz_api_key` | 空 | STRATZ Token；访问 STRATZ 时必须提供 |

OpenDota 与 STRATZ 共用上述每分钟及每日请求预算，缓存按数据源分别保存。请求预算是插件自己的保守限制，不是对任一数据源当前套餐额度的声明。即使本地预算尚有剩余，数据源也可能限流。

密钥由管理员自行提供；本项目不会寻找或导入本机其他应用的凭据。面板只显示密钥是否已配置，不回显内容；密钥输入框留空表示保留已有值，清除密钥需要显式选择清除。

整次查询另设 45 秒总时限；同一时间只处理一个查询，忙碌时返回明确提示。查询进行中不能修改设置，以免分页前后统计口径变化。英雄字典缓存一天，聚合英雄榜缓存 30 分钟；普通查询采用面板配置的缓存时间。

## 数据口径

当前接入 [OpenDota](https://docs.opendota.com/) 与 [STRATZ](https://docs.stratz.com/) 的只读数据查询。本地 SQLite 保存绑定、缓存和查询摘要，不保存聊天原文，也不与 AstrBot 人格数据库共用表。

| 查询内容 | 数据源选择 |
| --- | --- |
| 玩家资料、个人对局列表、单场详情 | 按 `data_source_priority` 选主源，符合条件时可回退 |
| 条件战绩、英雄池、多人对比 | 使用上述个人对局列表进行筛选和计算 |
| 英雄字典、聚合英雄榜 | 固定使用 OpenDota，不受优先源设置影响 |

只有初次取数失败且开启回退时，才尝试另一可用来源；正常的空结果不是接口失败，不会因此换源。个人战绩分页一旦选定来源，后续页固定使用该来源，避免把两个来源的分页记录悄悄混在一起。结果记录实际使用的数据源及覆盖范围；使用多个账号做比较时，仍需留意各账号取到的数据来源和完整程度。

STRATZ 需要管理员提供 Token。本版已用有效 Token 验证公开职业玩家的资料、对局列表、单场及英雄／胜负组合筛选；Token 不随仓库提供。其他账号的隐私和接口权限可能不同，有限样本验证不代表所有账号均可读取。

英雄字典读取失败时，已取得的 STRATZ 对局仍可返回英雄 ID；常见内置别名与明确数字 ID 可继续用于筛选。无法确定的英文或其他别名会要求补充信息，不猜测英雄。两个来源的玩家槽位和版本编号不直接互换，返回值保留独立字段。

- 玩家隐私设置、采集延迟和解析状态会影响可取得的数据。
- 达到扫描上限的结果属于有限覆盖，不能当作完整赛季或整月统计。
- “接口失败”“没有符合条件的对局”“尚未解析”是不同结果。
- 没有时间线或团战细节时，结果不能证明某个具体操作导致输赢。
- 聚合英雄统计不自动等于当前补丁的纯净样本，不保证覆盖任意分段或位置。
- 缓存结果带更新时间；过去取到的数据不应被当作实时数据。

## 暂未实现

职业赛事与转会信息、自动播报、定时报告、图片战报、自动提交录像解析、任意位置的精确筛选，以及独立的自然语言面板聊天功能均不属于这次开发版本。

## 后续验收

详见 [验收清单](docs/ACCEPTANCE.md) 与 [测试报告](docs/TEST_REPORT.md)。本仓库没有配置自动运行 CI。

离线测试不访问外网，也不启动或修改正式 Bot：

```shell
python -B tests/run_tests.py --astrbot-app /path/to/astrbot/app
```

使用含 `aiohttp`、`tzdata` 和 AstrBot 依赖的 Python。`--astrbot-app` 指向包含 `astrbot` 包的目录；不提供且 Python 中没有 AstrBot 时，框架测试会明确跳过。测试数据只写入已忽略的 `.test-tmp/`，运行前会覆盖 `ASTRBOT_ROOT` 为隔离目录。

`tests/live_queries.py` 是明确选择运行的联网测试；可通过 `--stratz-token-file` 提供本地 Token 文件。它使用公开职业账号，每轮限制为 20 次外部请求，不读取现有 Bot 配置。不要提交真实密钥或测试数据库。
