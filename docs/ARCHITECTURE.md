# 架构说明

版本：`0.2.1-dev`。本文描述代码职责与设计边界；已执行范围见 [测试报告](TEST_REPORT.md)，正式 Bot 链路仍待验收。

## 数据流

```text
现有 AstrBot 对话（当前人格、历史、原有陪伴功能）
  → 主模型决定调用 Dota2 工具
  → main.py 校验工具参数并获取真实会话／发送者身份
  → DataService 解析账号、时间和条件
  → 按数据类型及优先级选择 OpenDota／STRATZ 只读接口或对应缓存
  → 程序计算统计，返回事实、来源和覆盖范围
  → 原主模型继续回答
```

工具不会自行发出面向用户的消息。没有注册用于接管普通聊天的关键词或全消息监听器，也不调用另一个 LLM 来生成一份独立人设的报告。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 工具注册、事件身份、配置与面板 API 接入 |
| `dota_data/` | 参数验证、公开数据适配、缓存、绑定与统计 |
| `_conf_schema.json` | 插件配置字段及默认值 |
| `pages/dashboard/` | AstrBot iframe 内的管理页面，已通过本机框架目录发现测试 |

前端通过 `AstrBotPluginView`／`AstrBotPluginPage` bridge 访问后端。后端 API 由 AstrBot 的已认证 Dashboard 转发；部署时不另开端口或添加独立登录系统。绑定管理属于管理面板能力，聊天工具只处理当前发送者自己的绑定。

## 工具职责

- `dota2_query`：读取资料、战绩、单场、英雄池、比较或聚合英雄数据。查询参数只影响数据筛选。
- `dota2_manage_binding`：使用 `bind`、`unbind`、`show` 管理或查看本人在当前会话的绑定。`bind` 需要本条用户请求中明确写出数字账号 ID。

聊天中的写操作分两步：先提出修改并返回待确认信息，再由用户在下一条消息明确回复“确认”，工具以 `confirm=true` 完成操作。待确认内容按会话与发送者隔离，在内存保留五分钟，重载后失效。确认时使用已保存的待办内容，不能替换成模型临时传入的其他账号。

会话和发送者 ID 来自 AstrBot 事件，不由模型指定；查询其他公开账号不赋予修改其他人的绑定的权限。面板管理员可以按会话及用户管理绑定。

## 身份与持久化

绑定以 `scope + user_id` 定位。相同平台用户在不同会话中没有隐式共享绑定；需要时可以分别设置。别名作为便利索引，不能代替账号 ID 或身份校验。

SQLite 是插件自己的数据文件，仅保存必要的绑定、缓存和有限查询摘要。缓存过期不删除绑定。面板清缓存不应影响人格、记忆库、其他插件或账号对应关系。

查询摘要用于排障，不存储用户聊天原文、API Key 或完整对话上下文。API Key 通过配置提供，面板读取设置时只返回“是否已配置”，不回显密钥。

## 数据源与回退

`data_source_priority` 默认 `opendota`，可设置为 `stratz`；`fallback_enabled` 默认开启。STRATZ 必须配置 `stratz_api_key` 才能使用，代码不寻找或导入其他应用保存的凭据。

STRATZ 适配玩家资料、个人对局列表及单场详情，个人对局列表进一步支持条件战绩、英雄池和多人比较。英雄字典与聚合英雄榜固定来自 OpenDota 的 `/heroes`、`/heroStats`，不因选择 STRATZ 优先而改用不存在的等价查询。

回退只在初次取数失败且允许回退时发生；空数组或没有公开数据是有效结果，不自动切换来源。对 `/players/{id}/matches` 的一次分页读取会固定实际选定的来源，后续页失败时不悄悄转到另一来源继续拼接。各结果保留实际来源，避免把补充来源误写成主源数据。

两种数据源共享请求预算，缓存键包含来源。更换优先级不会把一种来源的缓存伪装成另一种来源。不同接口能取得的字段不完全一致，适配结果应保留缺失状态与覆盖限制。

STRATZ GraphQL 已使用用户提供的 Token 完成公开职业账号样本验证，覆盖资料、列表、详情和组合筛选；不把这一结果推广为所有权限和账号均已验证。

## 查询语义

日期词按配置时区转换为具体时间窗口；不同用户的比较使用相同窗口和筛选条件。已扫描数量、样本数量和是否受到扫描上限影响应随结果返回。

“最近十场斧王”先按英雄筛选，再取十场。没有找到十场时应交代实际样本及覆盖范围，不用其他英雄补足。

共同对局比较按比赛 ID 交集进行。仅凭出现在同一场比赛中，不能推断双方一定组队排队；若需要声明同队或同一 party，必须另有对应字段作为证据。

英雄池和版本聚合接口各有自身统计口径，不强行伪装成与个人战绩相同的日期窗口。数据缺失使用缺失状态表达，不把缺失值当作真实的零。

本版英雄池由相同条件下取到的最近对局分组计算，并非完整生涯英雄池。日期窗口默认最近 7 个自然日（含今天）；要查不限定日期的最近 N 场，主模型须传 `period=all`。参数未声明的筛选条件会明确拒绝，不静默忽略。

## 成本与失败处理

缓存、共享请求预算、超时、分页及扫描上限共同限制资源消耗。回退到另一数据源发出的请求也计入预算，不重置计数。该插件不调用聊天、嵌入或重排序模型；原主模型的正常工具调用仍可能产生模型费用。

数据源鉴权失败、限流、超时与真实空结果应被区分。不会为了取得更多信息而自动提交录像解析，不启动后台比赛监听，不自行重试到无限等待。

## 人格边界

插件不写人格文件或人格数据库，不注入角色身份，不清空会话历史，不改记忆和陪伴插件配置。工具返回内容是数据，不是高优先级角色指令。

主模型对工具的选择和最终措辞仍有模型行为的不确定性。因此后续必须验证完整对话流程；仅阅读代码不能证明模型永远不会出现角色表达变化。
